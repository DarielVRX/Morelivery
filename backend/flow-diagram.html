Punto de Entrada

  • server.js — arranca HTTP y schedulers
  • app.js — configura Express
  • bootstrap/ — middleware, rutas, loops

Módulos Principales

  • auth — JWT, OAuth, 2FA, email
  • orders — ciclo completo de pedido
  • drivers — disponibilidad, GPS, ganancias
  • events — SSE Hub para tiempo real

Motor de Asignación

  • candidate-finder — busca drivers
  • candidate-evaluator — scoring
  • kitchen — tiempos de prep
  • rebalancer — optimiza rutas
  • escalation — relaja criterios

Stack Tecnológico

Express 4.19 PostgreSQL Redis 4.6 JWT Zod 3.23 Web Push Stripe

Sistema de Tiempo Real (SSE)

Cómo el backend hace broadcasting de eventos a los clientes conectados sin WebSockets.

Ciclo SSE — Conexión y Eventos

sequenceDiagram participant FE as Frontend (EventSource) participant RT as events/routes.js participant AU as auth.js participant HB as events/hub.js (SseHub) participant MOD as Cualquier Módulo participant DB as PostgreSQL FE->>RT: GET /api/events?token=JWT RT->>AU: authenticate(req) AU-->>RT: { userId, role } RT->>HB: hub.register(userId, role, res) HB->>HB: clients.set(clientId, { res, userId, role }) RT->>FE: Headers SSE (text/event-stream) RT->>FE: event: connected\ndata: { clientId } loop Ping cada 25s (evita timeout de Render) RT->>FE: : ping end Note over MOD: Cualquier operación que\ngenera un evento MOD->>DB: UPDATE order status MOD->>HB: hub.sendToUser(userId, 'order_update', data) HB->>HB: Buscar clientes de userId HB->>FE: event: order_update\ndata: { orderId, status, ... } MOD->>HB: hub.notifyNewOffer(driverId, offerId, data) HB->>FE: event: new_offer\ndata: { orderId, restaurant, fee, ... } Note over FE: Usuario cierra tab/app FE->>RT: Conexión cerrada RT->>HB: hub.unregister(clientId) HB->>HB: clients.delete(clientId)
